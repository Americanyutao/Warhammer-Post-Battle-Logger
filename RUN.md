# Tray-only release

Run `release/WH3BattleLogger/WH3BattleLogger.exe`. Keep its `_internal` folder beside it. No Python installation is needed for this build. The app runs in the Windows notification area without a window or console.

Right-click the **LOG** icon for **Open reports** (opens the captures folder in File Explorer) or **Exit** (finishes saving before closing). Launch before deployment and leave it running through the results screen. Captures, HTML reports and their private `logger.key` are created in `captures` beside the executable. Keep that key with the encrypted captures.

The debugging window remains available through `Run-Battle-Logger.cmd`. The source tray launcher is `Run-Battle-Logger-Release.cmd`. Both use the updated LOG icon.

Build: `py -3 -B tools/build_release.py` using the workspace-local packaging dependencies. Packaged checks: `py -3 -B tools/check_release.py` in a normal Windows desktop session.

1. Double-click Run-Battle-Logger.cmd. The launcher starts Python without a console and closes its command window. This prototype uses 64-bit Python with Tk and cryptography (already present on this PC); it is not packaged as an EXE yet.
2. Use **Always on top: Off/On** in the live window header to pin or unpin it. Start a controlled single-player battle. Launching before deployment gives the best coverage. Collection starts automatically when the roster becomes available.
3. Enable **Live debug · includes hidden enemies** to inspect values. Select My units / All friendly / Enemy, then a row. Sampled state durations, firing/other damage estimates and first observed engagement are shown directly; scroll for raw values. Advanced statistics adds extra observations. Brief idle flickers under 3 simulation seconds stay inside the first engagement; interrupted/ongoing windows are incomplete.
4. Refresh rate defaults to **1× per second**; select **0.5×** (every 2 seconds) or **0.2×** (every 5 seconds). This controls reading and display. It is wall-clock sampling; durations use simulation seconds, so pause adds no duration and fast-forward advances the recorded clock faster.
5. Test idle/move/walk/run, shooting versus melee, pause/normal/fast-forward, off-camera and hidden enemies, healing single and multi-model units, barrier, summons and a second battle. Compare values against unit cards and tooltips. Unknown means not bound or unreadable, not zero.
6. On returning out of battle, the logger finalizes an encrypted .wh3log and a readable .html report under captures/. **Finish capture** ends it manually; that battle will not start another capture automatically. Closing the logger also saves and finalizes. Wait for saving to finish.
7. Click **Open report** after capture finishes. The Main view defaults to Simple; choose Damage breakdown for percentages and source types. Choose other statistic categories as needed. Select a unit for its sticky name/card header and ten shared information views. Arrange & hide views saves the layout across unit selections. Four views are configurable graphs, five are placeholders; Movement & occupancy combines the time-colored path and heatmap. All four graph selectors share the same options and preserve choices across units. Existing recorded values and Winds remain under Recorded statistics & timelines. The top-right Allied/Enemy/All selector applies to both views. Reports open separately and contain readable battle data. They are not encrypted.

Keep captures/logger.key with your captures. Logs use AES-256-GCM with a separate randomly generated 32-byte key; losing it makes those logs unreadable. The key is not a multiplayer lock: the local owner can decrypt logs during a battle. No reports are displayed automatically mid-battle.

Interpretation: native damage/kills/gold/source totals are reused; HP is the ordinary-battle cached value. States, concealment, movement, HP/models/barrier and ammo require live validation on this build. HP changes are net changes; model increases can miss simultaneous death/resurrection. Firing-state damage is an estimate, separate from the new native source totals. Raw regeneration is not applied healing. Revision-3 captures read the native remaining healing budget directly for single and multi-model units, rather than using the multi-model-clamped display ceiling. Restart the logger before capturing it. The recorded budget is used as-is; 75% is a test baseline, never a replacement for missing data. Legacy captures cannot recover this budget. Actual healing received remains unbound. Damage taken is calculated as initial minus current unclamped healing ceiling, with the assumptions available on hover. Budget or maximum-HP changes invalidate it; it is not an exact native incoming-damage counter. Winds generation/spending, individual ability use, exact orders, charging time, crumbling effects and actual battle outcome remain unbound. Missing units retain their last observed data with a missing label. Timestamped last-known maximum HP/model baselines survive cache shutdown at death without being relabeled as current values.

Healing cap remaining means the unclamped ceiling fraction × max HP (HP + remaining budget); Healing budget left is the spare budget alone.

Healing received is calculated as current HP + calculated damage taken - starting maximum HP, requiring a full-health baseline. This equals healing budget spent under the existing damage formula; it is not an independent record of heals that bypass the budget.

Trade = gold damage dealt / own unit value ×100. Base multiplayer values are used only when unambiguous; these omit ranks, abilities, gear and campaign adjustments. Select a unit and edit Unit value for this battle; zero or unknown values show no Trade percentage. Captured explicit values take priority over database defaults, and manual values override both.
